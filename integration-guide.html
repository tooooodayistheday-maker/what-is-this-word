REST API 連線設定

詞彙 Base URL：

https://workshub-word-notes-api.tooooodayistheday.chatgpt.site

名稱已獨立命名，網址為維持既有串接保留舊字樣。API 僅接受 GET；回應為 application/json; charset=utf-8。以下範例皆為格式示意，不含可用憑證。

驗證每次擇一

Authorization: Bearer <WORDS_BEARER_TOKEN>
或
X-API-Key: <WORDS_API_KEY>
或
Authorization: Basic <Base64(username:password)>

Basic 使用平台的使用者名稱與密碼欄位產生標頭。不要把憑證放進網址；不要同時送 Authorization 與 X-API-Key。憑證由服務擁有者另行提供，詞彙與河狸各自使用對應憑證。

詞彙路徑

GET /api/v1/words
GET /api/v1/words/{id}
GET /api/v1/words/latest
GET /api/v1/words/random
GET /api/v1/categories

單筆、最新與隨機端點直接回傳物件；清單回傳下列封套。ID 使用字串，保留前導零，例如 003。

{"data":[{"id":"003","title":"敵意建築","category":"城市與空間","is_test":false}],"next_cursor":null,"total":1}

上例為精簡結構示意，實際詞彙欄位包括：id, title, category, life_context, summary, act1, act2, act3, primary_source_url, source_count, url, published_date, updated_at, is_test；也可能包含額外來源欄位。日期為 ISO 8601；source_count 為數字，is_test 為布林值。

清單參數與分頁對應

  • limit：預設 20，範圍 1–50。
  • cursor：原樣傳回上一頁的 next_cursor，null 時停止。
  • category：分類名稱或 categories 的 id。
  • q：關鍵字，最多 200 字元。
  • updated_after：只取 updated_at 嚴格晚於指定 ISO 日期／時間的資料。含時區的加號應做 URL 編碼。

資料陣列路徑為 $.data，下一頁游標路徑為 $.next_cursor，下次請求參數名稱為 cursor。total 是篩選後、分頁前總數。改篩選條件時清除 cursor；來源更新造成 cursor_expired 時從第一頁重新讀取，並以 id 去重。清單可能包含測試資料，正式處理須自行排除 is_test=true。

GET /api/v1/words?limit=2&q=%E5%9F%8E%E5%B8%82
Accept: application/json
Authorization: Bearer <另行提供的詞彙金鑰>

API 錯誤

{"error":{"code":"unauthorized","message":"缺少或無效的驗證憑證；請擇一使用 Bearer、X-API-Key 或 Basic Auth。"}}

401：憑證無效；400：參數或游標問題；404：資料不存在；405：方法錯誤；502：資料來源暫不可用；503：服務尚未設定完成。若收到 HTML 而非 JSON，先檢查託管入口、登入或防火牆，不要當成業務資料解析。

無憑證靜態 JSON 備案

詞彙完整 JSON 是公開、不分頁的快照；回傳 data、next_cursor=null、total。它不會替你執行驗證、篩選或游標分頁，這些須在平台端處理。可用於先測中文、emoji 與欄位對應。

河狸 API 為另一組獨立服務

若也要河狸資料，請參考完整雙服務 API 文件；該文件含河狸 Base URL、facts、facts/{id}、facts/latest、facts/today 與 categories，以及 request／response 範例。目前詞彙 MCP 沒有河狸工具，不能以 MCP 呼叫 facts。

MCP 連線設定

顯示名稱：這個詞，是什麼？
端點：https://workshub-word-notes-api.tooooodayistheday.chatgpt.site/mcp
傳輸：無狀態 HTTP POST JSON-RPC 2.0
Content-Type: application/json
Accept: application/json, text/event-stream

現有實作回傳 JSON，不使用持續 SSE 事件流，不簽發 MCP session ID。GET /mcp 不是查資料入口，應回 405；只有 GET 連接器無法直接使用它。平台須有 MCP 用戶端，或自行實作協定轉接。

程式宣告支援版本 2026-07-28, 2025-11-25, 2025-06-18, 2025-03-26，提供 server/discover 與 initialize 相容路徑。這是程式宣告，不代表每個 SDK 的每個版本皆已互通。請以對方 SDK 的協商與實測結果判定。

驗證不能沿用 API 設定推論

MCP 的平台入口由 Sites 處理登入與呼叫者存取檢查。REST API 的 Bearer、X-API-Key、Basic 是 /api/v1 的驗證，不是本頁承諾的 MCP 登入方式。請確認平台可完成遠端服務的授權探索、OAuth 與權杖維護；若要求 client_id 等資料，先回報實際需求。本頁不提供共用登入權杖或繞過授權憑證。

三項唯讀工具

search_words
arguments: {"query":"城市","limit":5}
query：必要，非空字串，最多 100 字元。
limit：選填整數，預設 5，範圍 1–10。
搜尋 title、life_context、summary；回傳 {data:[精簡詞彙],total:符合數量}。
total 可能大於 data.length，目前無游標。

get_word
arguments: {"word_id":"003"}
word_id：必要字串，保留前導零。應先搜尋取得 ID。
回傳完整單筆詞彙，包含三幕正文與文章連結。

random_word
arguments: {}
回傳隨機完整單筆詞彙。連續呼叫不保證不同。

三項工具均排除 is_test=true；不提供寫入、排程或發文。

JSON-RPC 測試順序

以下是請求範例；使用標準 MCP SDK 時，讓 SDK 處理初始化與協商。不同請求使用不同 id。

{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"integration-test","version":"1.0.0"}}}

{"jsonrpc":"2.0","method":"notifications/initialized"}

{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}

{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"search_words","arguments":{"query":"敵意建築","limit":5}}}

{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"get_word","arguments":{"word_id":"003"}}}

{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"random_word","arguments":{}}}

若 SDK 採 server/discover，程式也有相應處理。通知回 HTTP 202。成功工具回應包含 result.content（text 中為 JSON 字串）、result.structuredContent（可直接對應欄位）及 result.isError=false。請勿把 content 的 JSON 字串當成已解析物件。

{"jsonrpc":"2.0","id":3,"result":{"content":[{"type":"text","text":"{\"data\":[],\"total\":0}"}],"structuredContent":{"data":[],"total":0},"isError":false}}

上例為「沒有搜尋結果」的示意，屬正常結果。工具失敗可能仍回 HTTP 200，但 result.isError=true，且 content 有原因；協定錯誤使用頂層 error，不能只檢查 HTTP 狀態。平台入口的 401／403 則屬登入、授權或網路層問題。

請依這份驗收清單回報

  1. 列出平台名稱、版本與實際可用連接器。若只能 GET，先選 API，不把 URL 貼入後稱作 MCP。
  2. 先讀公開 JSON，確認 UTF-8 中文、emoji、字串 ID、數字、布林值與換行未破壞。
  3. API：憑證擇一測試清單、單筆、隨機；limit=2 讀下一頁直到 next_cursor=null，檢查無漏筆及重複；測試錯誤金鑰 401、錯誤參數 400、缺少 ID 404。
  4. MCP：完成正常授權與初始化；tools/list 找到三項工具；實際搜尋後用返回的 ID 讀文章，再隨機抽詞。確認工具輸出與網站連結一致。
  5. 用自然語言測試「找城市生活相關詞」「讀取找到的第一個詞」「隨機出一題，先隱藏答案」。確認是平台 AI 真正選用工具，而非模型憑記憶回答。
  6. 若 403 或授權失敗，記錄時間、方法、狀態碼與不含憑證的錯誤摘要；停止並回報，不繞過防護。
